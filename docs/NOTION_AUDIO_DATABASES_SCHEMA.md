# Notion Audio Databases Schema Documentation

This document provides detailed schema documentation for the audio-related Notion databases used in the content generation pipeline.

## Overview

The system uses two interconnected Notion databases to manage audio content production:

1. **Voices for Text-to-Speech** - Catalog of available TTS voices with their characteristics
2. **Audio Database** - Content items with audio generation and publishing status

---

## 1. Voices for Text-to-Speech Database

**Database ID**: `303dd30aa93a8085b3a3dd5b10867276`  
**Purpose**: Manage and catalog text-to-speech voices from various providers with detailed metadata about voice characteristics.

### Properties

| Property | Type | Description | Values/Options |
|----------|------|-------------|----------------|
| **Name** | Title | Voice name identifier | Text (title field) |
| **Description** | Text | Detailed description of the voice characteristics | Rich text |
| **Provider** | Select | TTS service provider | `elevenlabs` |
| **Voice ID** | Text | Unique identifier for the voice in the provider's system | Plain text |
| **Link** | URL | Direct link to voice sample or provider page | URL |
| **Languages** | Multi-select | Supported languages | `en`, `zh` |
| **Accent** | Multi-select | Regional accent variations | `American`, `British` |
| **Gender** | Select | Voice gender | `female`, `male`, `any` |
| **Age Range** | Select | Apparent age of the voice | `adult`, `child`, `elderly` |
| **Specialties** | Multi-select | Use cases the voice excels at | `conversation`, `narration`, `meditation`, `story` |
| **Comment** | Text | Additional notes or observations | Rich text |

### Views

1. **All** - Complete table view showing all voices with all properties
2. **Male - English** - Filtered view for male English voices
3. **Female - English** - Filtered view for female English voices

### SQLite Schema

```sql
CREATE TABLE IF NOT EXISTS "collection://303dd30a-a93a-80f0-a879-000be1ec419e" (
    url TEXT UNIQUE,
    createdTime TEXT, -- ISO-8601 datetime string
    "Age Range" TEXT, -- one of ["adult", "child", "elderly"]
    "Comment" TEXT,
    "Accent" TEXT, -- JSON array with zero or more of ["American", "British"]
    "Gender" TEXT, -- one of ["female", "male", "any"]
    "Voice ID" TEXT,
    "Description" TEXT,
    "Specialties" TEXT, -- JSON array with zero or more of ["conversation", "narration", "meditation", "story"]
    "Languages" TEXT, -- JSON array with zero or more of ["en", "zh"]
    "Provider" TEXT, -- one of ["elevenlabs"]
    "Link" TEXT,
    "Name" TEXT
)
```

### Usage Notes

- **Voice ID** is critical for programmatic voice selection in TTS API calls
- **Specialties** help match voices to content types (e.g., meditation content should use meditation-specialized voices)
- **Accent** and **Gender** allow for demographic targeting and voice variety
- This database is referenced by the Audio Database through the **Voices** relation property

## 2. Audio Database

**Database ID**: `302dd30aa93a8087be8dda41b3b4de9b`  
**Purpose**: Track audio content items from creation through publication across multiple platforms.

### Properties

| Property | Type | Description | Values/Options |
|----------|------|-------------|----------------|
| **id** | Auto-increment ID | Unique numeric identifier | Auto-generated integer |
| **Name** | Title | Content item name/identifier | Text (title field) |
| **Title** | Text | Display title for the content | Plain text |
| **Description** | Text | Content description or summary | Rich text |
| **Topic** | Select | Content topic/category | `2in` |
| **Sub-Type** | Select | Content sub-category | `meditation`, `teachings` |
| **Content** | Text | Full text content/script | Rich text |
| **Tags** | Text | Comma-separated tags for categorization | Plain text |
| **Status** | Status | Production workflow status | `Not started`, `Ready for Audio`, `In progress`, `Published`, `Cancelled` |
| **Target Platforms** | Multi-select | Intended distribution channels | `YouTube Shorts`, `YouTube`, `Tiktok`, `Instagram Reels` |
| **URL** | URL | Published content URL | URL |
| **Published Date** | Date | Publication date/time | Date or datetime |
| **Duration Min** | Number | Minimum duration in seconds/minutes | Float |
| **Duration Max** | Number | Maximum duration in seconds/minutes | Float |
| **Content Generated By** | Multi-select | AI tools used for generation | `deep-research`, `claude` |
| **Voices** | Relation | Selected TTS voices for this content | Relations to Voices database |
| **Parent Content** | Relation (self) | Parent content item if hierarchical | Relations to same database |
| **Child Contents** | Relation (self) | Child content items | Relations to same database |
| **Created time** | Created time | When the record was created | Timestamp (auto) |
| **Created by** | Created by | Who created the record | Person (auto) |
| **Last edited time** | Last edited time | Last modification timestamp | Timestamp (auto) |
| **Last edited by** | Last edited by | Last person to edit | Person (auto) |

### Status Workflow

The **Status** property uses grouped statuses for workflow management:

- **To-do group**: `Not started`
- **In-progress group**: `Ready for Audio`, `In progress`
- **Complete group**: `Published`, `Cancelled`

### Views

1. **Active** - Table view with all active content showing all properties
2. **To-do** - Gallery view filtered for items in to-do status
3. **Ready-for-Audio** - Gallery view for items ready for audio generation

### SQLite Schema

```sql
CREATE TABLE IF NOT EXISTS "collection://302dd30a-a93a-80a4-8c7d-000b7c519611" (
    url TEXT UNIQUE,
    createdTime TEXT, -- ISO-8601 datetime string
    "Content" TEXT,
    "Child Contents" TEXT, -- JSON array of page URLs (self-referential)
    "Topic" TEXT, -- one of ["2in"]
    "Content Generated By" TEXT, -- JSON array with zero or more of ["deep-research", "claude"]
    "Duration Max" FLOAT,
    "Last edited time" TEXT NOT NULL,
    "Tags" TEXT,
    "Created by" TEXT,
    "Sub-Type" TEXT, -- one of ["meditation", "teachings"]
    "Status" TEXT, -- one of ["Not started", "Ready for Audio", "In progress", "Cancelled", "Published"]
    "userDefined:URL" TEXT,
    "Duration Min" FLOAT,
    "userDefined:id" INTEGER,
    "Title" TEXT,
    "Parent Content" TEXT, -- JSON array of page URLs (self-referential)
    "Voices" TEXT, -- JSON array of page URLs to Voices database
    "Last edited by" TEXT,
    "Created time" TEXT NOT NULL,
    "date:Published Date:start" TEXT, -- ISO-8601 date or datetime
    "date:Published Date:end" TEXT, -- ISO-8601 date or datetime (for ranges)
    "date:Published Date:is_datetime" INTEGER, -- 1 for datetime, 0 for date
    "Description" TEXT,
    "Target Platforms" TEXT, -- JSON array with zero or more of ["YouTube Shorts", "YouTube", "Tiktok", "Instagram Reels"]
    "Name" TEXT
)
```

### Relationships

#### Voices Relation
- **Type**: Many-to-many
- **Target**: Voices for Text-to-Speech database (`collection://303dd30a-a93a-80f0-a879-000be1ec419e`)
- **Usage**: Link audio content to one or more TTS voices for generation

#### Hierarchical Relations
- **Parent Content** and **Child Contents** provide hierarchical organization
- **Type**: Self-referential relations within the same database
- **Usage**: Group related content items (e.g., series episodes, multi-part content)

### Usage Notes

- **Content Generated By** tracks which AI tools were used, helpful for quality analysis
- **Duration Min/Max** define acceptable length ranges for platform-specific requirements
- **Target Platforms** determines format and optimization requirements
- **Status** workflow supports a production pipeline from ideation through publication
- The **Voices** relation must reference valid entries from the Voices for Text-to-Speech database
- **Published Date** uses expanded properties in SQLite for date handling

## Integration Points

### API Access

Both databases can be accessed via:
- Notion API using the database IDs
- SQL queries using the collection URLs
- Python SDK with the `notion_client` library

### Property Naming Conventions

Note the special handling for certain property names:
- Properties named `id` or `URL` must be prefixed with `userDefined:` in API calls
- Date properties use expanded notation: `date:<property>:start`, `date:<property>:end`, `date:<property>:is_datetime`
- Multi-select and relation properties return JSON arrays in SQLite format

### Example Queries

#### Get all English meditation voices
```python
# Filter Voices database for meditation specialty and English language
voices = notion.databases.query(
    database_id="303dd30aa93a8085b3a3dd5b10867276",
    filter={
        "and": [
            {"property": "Languages", "multi_select": {"contains": "en"}},
            {"property": "Specialties", "multi_select": {"contains": "meditation"}}
        ]
    }
)
```

#### Get audio content ready for generation
```python
# Query Audio Database for items in "Ready for Audio" status
content = notion.databases.query(
    database_id="302dd30aa93a8087be8dda41b3b4de9b",
    filter={
        "property": "Status",
        "status": {"equals": "Ready for Audio"}
    }
)
```

## Maintenance

### Adding New Properties

When adding properties to either database:
1. Update the Notion database schema first
2. Update this documentation
3. Update any related Python models or type definitions
4. Update validation schemas if applicable
5. Test API integrations

### Migration Considerations

- Always backup database contents before schema changes
- Test relation properties carefully when modifying connected databases
- Date property changes require special handling of expanded properties
- Status property groups should maintain workflow integrity
